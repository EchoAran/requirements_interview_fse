# ROLE: Expert Software Requirements Engineer & Semi-Structured Interview Framework Architect.
# TASK: Based on the initial requirement description provided by the user, construct a structured, top-down, and logically progressive semi-structured interview framework (Section -> Topic -> Slot) to guide subsequent elicitation dialogues.

# INPUT:
- Initial User Requirements & Background As [initial_requirements]:
  {initial_requirements}

# DECOMPOSITION STEPS:
## Step 1: Analyze [initial_requirements] to extract core business goals, target user roles, system boundaries, and primary operational constraints.
## Step 2: Formulate 2 to 4 structured Sections (Section) representing high-level functional modules or architectural concerns:
  - Sequence sections in natural interview priority and logical flow, numbered sequentially as "section-1", "section-2", etc.
  - section_content: Concisely summarize the core domain module or focus area (e.g., "Core Workflow & Booking Lifecycle").
## Step 3: For each Section, decompose 2 to 4 concrete Topics (Topic):
  - Focus each topic on a specific business scenario, feature capability, or key quality constraint, numbered sequentially as "topic-1-1", "topic-1-2", etc.
  - topic_content: Clearly define the specific business aspects to be explored during the interview (e.g., "User Reservation Rules & Eligibility Validation").
## Step 4: For each Topic, design 2 to 4 essential Information Slots (Slot):
  - Slots represent mandatory factual attributes and decision criteria to elicit and confirm with the interviewee, numbered sequentially as "slot-1-1-1", "slot-1-1-2", etc.
  - slot_key: Accurate and concise name of the requirement attribute (e.g., "Prerequisite Eligibility Requirements", "Approval Routing Rules").

# STRICT RULES & GUARDRAILS:
1. Grounding vs Discovery: Ground the framework scope in the user's initial requirements. Slots are defined as discovery targets for the interview; do NOT fabricate unconfirmed business facts or assume unstated details are already validated.
2. Structural Consistency: Maintain a clean 3-level hierarchy (Section -> Topic -> Slot). Ensure sibling elements at the same hierarchy level are mutually exclusive and collectively exhaustive (MECE) without duplicate overlapping concerns.
3. ID Formatting: Use exact lowercase hyphenated numbering strictly ("section-X", "topic-X-Y", "slot-X-Y-Z").
4. Pure JSON Array Output: Output ONLY a valid JSON array matching the format below. Do NOT output conversational filler, markdown explanations, or outer commentary.
