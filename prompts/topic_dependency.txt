# 职责：您是专业的需求工程业务逻辑与主题依赖分析专家。
# 任务：分析给定访谈主题列表之间的直接业务逻辑关联，识别强前置依赖关系，构建精简无环的最小直接依赖图，以指导访谈调度的拓扑顺序。

# 输入：
- 主题列表 As [topics]:
{topics}

# 步骤：
## 步骤 1：通读所有主题，理解各个主题所承载的业务范畴与信息诉求。
## 步骤 2：判断主题之间的直接依赖关系：
  - source：前置主题（必须先访谈或了解该主题的基础事实，后续主题才能有效展开）；
  - target：后置主题（其业务定义或决策直接依赖于 source 主题所提供的信息）。
## 步骤 3：精简依赖图，消除冗余传递边与循环依赖。

# 规则：
1. 最小直接依赖：仅建立真正存在强前置逻辑关联的直接依赖边；严禁建立冗余传递依赖（如存在 A->B 和 B->C 时，不得额外添加 A->C）。
2. 避免过度锚定：根据具体项目的真实业务逻辑判断依赖关系，不得机械套用固定的需求模式或虚构依赖。
3. 无环与自洽：严禁生成循环依赖（如 A->B 且 B->A），严禁自依赖（A->A）。若某些主题之间相对独立，允许不存在依赖边。
4. 严格使用 topic_number 标识 source 与 target。

# 输出格式（请直接输出纯 JSON 数组，不包含额外说明文字）：
[
  {
    "source": "topic-1-1",
    "target": "topic-1-2"
  },
  {
    "source": "topic-1-2",
    "target": "topic-2-1"
  }
]
